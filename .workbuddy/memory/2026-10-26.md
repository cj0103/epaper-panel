# 2026-10-26 工作日志

## epaper-panel 新板（iDevice 整合驱动板 ESP32-S3）适配排障

### 背景
旧板（分立墨水屏驱动板 + ESP32-S3）用同一套固件能点亮 7.5 寸盒马红白黑三色屏。
换 iDevice 整合板（板载 ESP32-S3 N16R8 + 墨水屏驱动）后：屏不刷新 + 串口无日志。

### 定位到的三个独立问题

**1. 串口日志全丢（最隐蔽，掩盖了其他问题）**
- 新板是 ESP32-S3 原生 USB（VID:PID=303A:1001 = USB Serial/JTAG），**没有 USB-UART 桥芯片**
- 原 FQBN `CDCOnBoot=default`（=禁用）时，Arduino 的 `Serial` 映射到 UART0(GPIO43/44)，该板上是空引脚 → app 日志全丢
- 现象极具迷惑性：ROM/bootloader 日志能打印（走芯片内部 USB 调试口），但 app 段一行不出，看起来像"setup 卡死"
- 修复：FQBN 加 `USBMode=hwcdc,CDCOnBoot=cdc,UploadMode=default`
- 教训：ESP32-S3 原生 USB 板必须显式开 CDCOnBoot，否则 Serial 无输出

**2. LittleFS 挂载 assert 死循环**
- 报错：`assert failed: lfs_fs_grow_ lfs.c:5272`
- 根因：Arduino core 的 `LittleFS.begin()` 内部 `conf.grow_on_mount = true`；
  换分区表后 flash 上残留超级块记录的 block_count 与新几何不匹配 → 扩卷断言崩死
- 修复：绕开 core 封装，用 `esp_vfs_littlefs_register` 自行挂载（`grow_on_mount=false`），
  挂不上则 `esp_partition_erase_range` 擦 spiffs 分区后重挂
- 注意：core 的 `begin(formatOnFail, basePath, maxOpenFiles, partitionLabel)` 第 4 参是**分区标签**，
  不是 formatOnFail（formatOnFail 是第 1 参）——之前一直误传
- 注意：IDF 枚举名是 `ESP_PARTITION_SUBTYPE_DATA_SPIFFS`（不是 `ESP_PARTITION_SUBTYPE_DATA`）；
  擦除函数是 `esp_partition_erase_range`（不是 `esp_partition_erase_all`）

**3. 屏驱动型号错误**
- 屏主控是 **UC8179**，但代码用的是 `GxEPD2_750c_GDEW075Z08`（GD7965）
- 已换为 `gdey3c/GxEPD2_750c_GDEY075Z08`（UC8179）
- 坑：`render_panel.h` 里的 `extern GxEPD2_3C<...> display;` 必须同步改，否则模板实例化冲突
  （报 "conflicting declaration"）
- GxEPD2 1.6.9 里两个 7.5 寸 800x480 三色驱动并存，控制器不同：
  - `epd3c/GxEPD2_750c_GDEW075Z08` → GD7965，busy_level=LOW，超时 20s
  - `gdey3c/GxEPD2_750c_GDEY075Z08` → UC8179，busy_level=LOW，超时 30s

### 当前状态（已验证）
固件全流程正常：LittleFS 挂载成功 → WiFi 连接成功（Xiaomi_8CC4）→ 路由注册 →
渲染 → display → IP http://192.168.31.12。**但屏仍不刷新**。

### 屏不刷新的根因（硬件层，尚未解决）
- 探针固件（`epd_probe.cpp`）实测：`Get Status(0x71)` 读回 **0xFF**（SPI 链路无应答），
  BUSY(GPIO15) 恒为 LOW 且 1.5 秒内零跳变
- 串口日志 `_PowerOn : 14757004`（14.7 秒）= GxEPD2 等 BUSY 等满超时，屏没应答
- 原厂 PCB 图丝印：**`epaper 2.13br`** —— 这块板是按 **2.13 寸三色屏 EPD213R** 设计的
- 24pin FPC 标准针序（UC8179 7.5" 800x480）：pin9=BUSYN, pin10=RSTN, pin11=D/C,
  pin12=CSB, pin13=SCL, pin14=SDA；pin2/3/5/8 是升压控制脚(GDR/RESE/VSHR/BS)，
  pin21-24 是 VGH/VSL/VGL/VCOM 高压输出
- 结论方向：**7.5 寸裸屏（含 24pin 排线）不能直接插这块板**——
  升压电路（GDR/RESE/VSHR/BS 控制 + VGH/VGL 高压输出）不匹配，
  板载接口的针序/电压是给 2.13 寸模组的
- 用户反馈昨天旧板点亮成功、今天新板跑不通，且"排线直接插新板"
  → 待确认：新板接口到底能不能吃 24pin 裸屏，还是必须用 2.13 寸模组/另配升压板

### 烧录/串口备忘
- COM 口会漂移：COM8 → COM9（每次复位/插拔可能变），用 `serial.tools.list_ports` 确认
- pyserial 读日志必须 `dsrdtr=False` + 打开后立刻 `s.dtr=False; s.rts=False`，
  否则默认拉 DTR 把板子按进下载模式
- 端口因 USB 重枚举消失时要自动重开（`tools/cap.py` 实现了容错抓取）
- esptool v5.3.0：`--after no-reset` 可留在 bootloader，`run` 命令可复位回运行模式
- 烧录参数：`esp32:esp32:esp32s3:FlashSize=16M,FlashMode=qio,PSRAM=opi,
  PartitionScheme=custom,USBMode=hwcdc,CDCOnBoot=cdc,UploadMode=default`
